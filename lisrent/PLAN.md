# 리스렌트 내부 프로그램 — 기능 검토 및 작업 계획

> 작성일: 2026-08-30
> 대상: 자동차 리스·렌트(장기렌트) 회사 내부 업무 관리 프로그램
> 상태: **v1 구현 완료 (Phase 1~2 + Phase 3 일부)** — 사용법은 `README.md` 참고
>
> 구현된 것: 고객/상담, 견적 계산기+견적서 출력, 계약 전환·상태 흐름·서류 첨부, 만기 관리,
> 대시보드, 차종·금융사 기준정보, 수수료 정산(CSV), 사용자 승인·역할, 감사 로그, RLS 보안
> 미구현(2단계): 알림톡/SMS 자동 발송, 엑셀 일괄 이관, 전자계약

---

## 1. 전제 확인 (착수 전 확정 필요)

아래 3가지에 따라 기능 범위가 크게 달라집니다. 계획은 가장 일반적인 **신차 장기렌트·리스 영업/중개형** 회사를 기준으로 세웠고, 자체 차량 보유형이면 Phase 3에 차량 운영 기능이 추가됩니다.

| 확인 항목 | 선택지 | 계획 기본값 |
|---|---|---|
| 사업 형태 | ① 신차 장기렌트·리스 영업/중개 (금융사 상품 판매) ② 자체 차량 보유 렌터카 운영 | ① 중개형 |
| 사용 인원 | 관리자 / 영업사원 몇 명이 쓰는지 | 3~15명 규모 |
| 알림 채널 | 카카오 알림톡 / SMS / 이메일 필요 여부 | 2단계에서 추가 |

## 2. 기본적으로 있으면 좋은 기능 (검토 결과)

### 필수 (MVP — 이것만 있어도 업무가 돌아감)

1. **고객 관리 (CRM)**
   - 개인/법인 구분, 연락처, 사업자 정보, 담당 영업사원
   - 상담 이력 메모 (날짜별 타임라인)
   - 고객 상태: 리드 → 상담중 → 견적 → 계약 → 운영중 → 만기
2. **견적 관리**
   - 차종/트림/옵션, 금융사(캐피탈), 계약기간(36/48/60개월), 보증금·선납금 비율, 잔가율
   - 월 납입료 계산 및 견적서 출력(PDF)
   - 견적 여러 건 비교 → 계약 전환
3. **계약 관리 (핵심)**
   - 계약 정보: 계약일, 인도(출고)일, 만기일, 월 납입료, 금융사, 차량번호
   - 계약 상태: 접수 → 심사 → 승인 → 출고 → 운영중 → 만기(재계약/반납/인수)
   - 계약서·서류 파일 첨부 (신분증, 사업자등록증, 계약서 스캔본)
4. **만기 관리** ← 리스렌트 업무의 매출 핵심
   - 만기 D-90 / D-60 / D-30 자동 리스트업
   - 만기 처리 결과 기록: 재계약 / 반납 / 인수
5. **대시보드**
   - 이달 계약 건수·매출, 만기 예정 건수, 영업사원별 실적
6. **사용자·권한 관리**
   - 관리자 / 영업사원 역할 구분 (영업사원은 본인 고객만 보기 옵션)

### 권장 (2단계 — 업무 자동화)

7. **수수료(커미션) 정산** — 계약별 금융사 수수료, 영업사원 지급률, 월별 정산표
8. **알림 자동화** — 만기 임박, 보험 갱신, 미수금 알림 (알림톡/SMS)
9. **보험·정비 관리** — 보험 만기일 추적, 사고 접수 기록
10. **제휴 금융사 관리** — 캐피탈별 이율/잔가/프로모션 조건표
11. **엑셀 내보내기/가져오기** — 기존 엑셀 데이터 이관, 정산 자료 다운로드

### 선택 (3단계 — 있으면 좋음)

12. 전자계약/전자서명 연동, 고객용 견적 공유 링크
13. 자체 차량 보유형인 경우: 차량 재고/배차/반납 점검, 정비 이력
14. 통계 리포트 (차종별/금융사별/기간별 분석)

## 3. 기술 스택 (제안)

| 구성 | 제안 | 이유 |
|---|---|---|
| 프론트엔드 | 정적 SPA (HTML/JS 또는 React) — 이 저장소 방식과 동일하게 GitHub Pages 서브경로 또는 별도 도메인 배포 | 기존 운영 방식(noahgroup.co.kr 정적 호스팅)과 일치, 서버 관리 불필요 |
| 백엔드/DB | **Supabase** (PostgreSQL + 인증 + 파일 스토리지 + Row Level Security) | 서버 없이 DB·로그인·파일첨부·권한까지 해결, 무료 티어로 시작 가능 |
| 인증 | Supabase Auth (이메일/비밀번호) + 역할(role) 기반 권한 | 내부용이므로 가입 차단, 관리자가 계정 발급 |
| 알림 (2단계) | 알림톡/SMS 발송 API (예: 솔라피, 알리고) + Supabase Edge Function 스케줄러 | 만기/미납 자동 알림 |

> 대안: 초기 인원이 2~3명이고 최대한 가볍게 가려면 Google Sheets + Apps Script로 시작할 수도 있으나, 계약·파일·권한 관리가 들어가는 순간 한계가 명확해 Supabase 방식을 권장.

## 5. 작업 계획 (Phase별)

### Phase 0 — 요구사항 확정 (½일)
- [ ] 위 "전제 확인" 3가지 답 받기 (사업 형태 / 인원 / 알림 채널)
- [ ] 기존에 쓰던 엑셀·수기 양식 확보 (필드 누락 방지)
- [ ] Supabase 프로젝트 생성 및 도메인/배포 위치 결정

### Phase 1 — 기반 구축 (1~2일)
- [ ] DB 스키마 생성 (customers, vehicles, financiers, quotes, contracts)
- [ ] Supabase Auth 연동, 로그인 화면, 역할별 접근 제어(RLS)
- [ ] 공통 레이아웃 (사이드바, 목록/상세/폼 패턴)

### Phase 2 — 핵심 업무 (3~5일) ← MVP 완성 지점
- [ ] 고객 관리: 목록/검색/등록/상세 + 상담 이력
- [ ] 견적 관리: 견적 등록, 월납입료 계산, 견적서 PDF 출력
- [ ] 계약 관리: 견적→계약 전환, 상태 흐름, 서류 파일 첨부
- [ ] 만기 관리: D-90/60/30 리스트, 만기 처리 기록
- [ ] 대시보드: 월 실적/만기 예정 요약
- [ ] 기존 엑셀 데이터 이관

### Phase 3 — 자동화·정산 (2~4일)
- [ ] 수수료 정산 (계약별 자동 계산, 월별 정산표, 엑셀 다운로드)
- [ ] 알림 자동화 (알림톡/SMS: 만기 임박, 보험 갱신)
- [ ] 금융사 조건표 관리
- [ ] (자체 보유형인 경우) 차량 재고/배차 관리

### Phase 4 — 마무리·운영 (1~2일)
- [ ] 권한 세분화, 감사 로그(누가 언제 수정했는지)
- [ ] 백업 정책, 사용자 매뉴얼
- [ ] 실사용 피드백 반영

**총 예상: MVP까지 약 5~8 작업일, 전체 2~3주**
