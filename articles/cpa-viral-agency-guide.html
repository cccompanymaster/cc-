목차
    한 줄 답

    CPA 광고회사는 DB 품질, 전환(과금) 정의, 업종 경험, 매체 분산, 리스크 공유 5가지를 계약 전에 확인해 고릅니다. 대행사가 내세우는 성과는 기간·광고비·측정 화면을 함께 받아 확인하고, 광고 계정·데이터·저작권은 계약서에 광고주 것으로 적어 둡니다.

    CPA·바이럴 대행사 견적서는 비슷해 보여도 DB를 세는 기준, 성과를 보여 주는 방식, 계약이 끝났을 때 광고주에게 남는 것이 다릅니다. 이 글은 계약 전에 확인할 5가지, 대행사 사례를 검증하는 법, 계약·인계 때 챙길 7가지를 정리합니다.

    1. CPA 광고회사 — 계약 전에 확인할 5가지

    1. DB 품질 투명성: 개인정보를 가린 DB 샘플을 요청합니다. 신청 일시·유입 매체·연락처 형식이 보여야 중복·허위 DB를 가려낼 수 있습니다.
    2. 전환(과금) 정의: '전환'이 상담 신청인지, 방문인지, 계약인지 계약서에 적습니다. 같은 '전환'이라도 정의가 다르면 단가를 서로 비교할 수 없습니다.
    3. 업종 경험: 같은 업종을 운영한 기록을 요청합니다. 캡처보다 광고 관리자·GA4 화면을 직접 보여 줄 수 있는 곳이 확인하기 쉽습니다.
    4. 매체 분산도: 한 매체에만 기대면 그 매체의 정책이 바뀔 때 DB가 한꺼번에 끊길 수 있습니다. 검색광고·블로그·SNS처럼 여러 매체를 쓰는지 봅니다.
    5. 리스크 공유: 무효 DB 교체, 성과 미달 때 재작업·일부 환불 같은 조항이 있는지 확인합니다.

    견적서 함정. "월 통합 OOO만 원" 견적은 매체비·운영비·제작비가 각각 얼마인지 알 수 없어 나중에 정산을 두고 다투기 쉽습니다. 매체비·운영비·콘텐츠 제작비·DB 단가를 나눈 항목별 견적을 받으세요.

    2. CPA 단가 — 시세표 대신 내 손익으로 계산하기

    업종별 단가 시세는 전환 정의와 무효 기준에 따라 크게 달라져 그대로 비교하기 어렵습니다. 내 사업의 손익으로 DB 1건에 쓸 수 있는 최대 금액을 먼저 계산하세요.

    • 계산식: DB 1건 최대 단가 = 계약 1건으로 남는 이익 × DB가 계약으로 이어지는 비율
    • 예시(가정): 신청 10건 중 1건이 계약되고 계약 1건 이익이 30만 원이라면 DB 1건에 쓸 수 있는 돈은 3만 원까지입니다
    항목계약 전에 정할 것
    전환 정의상담 신청·방문·계약 중 무엇을 1건으로 세는지
    무효 기준중복·결번·허위·서비스 지역 밖 DB를 어떻게 처리하는지
    검수 기간무효 DB를 신청할 수 있는 기간과 교체·환불 방식
    수집 동의제3자 제공이면 받는 자·목적·항목·보유 기간 고지 후 동의(개인정보 보호법 제17조), 위탁이면 위탁 문서와 공개(제26조)

    DB 정의와 무효 기준은 CPA 광고 칼럼에 자세히 정리했습니다.

    3. 바이럴 대행사 사례 — 검증하는 법

    대행사 소개서의 성공 사례는 기준과 근거가 함께 있어야 판단할 수 있습니다. 사례를 받으면 아래 다섯 가지를 확인하세요.

    • 기준점과 기간: 시작 전 수치와 측정 기간이 함께 있는가? 증가율만 있으면 무엇과 비교했는지 알 수 없습니다.
    • 들어간 비용: 같은 기간의 광고비·제작비가 함께 있는가?
    • 측정 화면: 캡처 대신 GA4·광고 관리자·플레이스 통계 화면을 직접 보여 줄 수 있는가? 비밀유지 계약이 있다면 업체명만 가린 화면이면 됩니다.
    • 대가 표시: 사례 속 체험단·인플루언서 글에 대가 표시가 있는가? 2024년 12월 1일부터 블로그 같은 글 게시물은 제목이나 글 첫 부분에 밝혀야 합니다.
    • 제재 이력: 대가를 숨긴 바이럴은 제재 대상입니다. 2019년 공정거래위원회는 인스타그램 인플루언서 광고에 대가를 밝히지 않은 7개 사업자에 시정명령과 과징금 총 2억 6,900만 원을 부과했습니다.

    공개 기록으로 확인되는 사례는 바이럴 마케팅 사례 칼럼에 모았습니다.

    4. 블로그 노출이 갑자기 줄었을 때

    흔히 '저품질'이라고 부르지만 업계에서 쓰는 말이고, 네이버가 판정 기준이나 회복 기간을 공개한 자료는 찾을 수 없습니다. 원인을 하나씩 좁혀 보세요.

    • 블로그 통계에서 유입 검색어·유입 경로가 언제부터 줄었는지 확인
    • 최근 글 제목으로 검색해 글 하나가 빠진 것인지, 블로그 전체가 줄어든 것인지 구분
    • 다른 곳의 문장·사진을 가져온 글이 없는지 확인 — 네이버는 2012년 검색 개편 때 원본 문서를 위에 노출하겠다고 밝혔습니다
    • 리워드 앱 등으로 검색·클릭을 만든 적이 없는지 확인 — 네이버는 2025년 6월 이용정책을 바꿔 리워드 앱을 이용한 검색 조작을 금지했습니다

    진단 순서는 블로그 저품질 칼럼에 자세히 정리했습니다.

    5. 광고 에이전시·마케팅 에이전시 평가 매트릭스

    평가 축우수 에이전시회피해야 할 에이전시
    견적항목별 세분 + 마진율 공개"통합 월 XXX만"
    포트폴리오같은 업종 운영 기록 + 측정 화면 공유상투적 화면 스크린샷만
    계약해지·위약 조항 명시 + 데이터 인계 의무구두 합의만
    리포트주간·월간 + 상담 + 데이터 직접 접근권월말 1회 텍스트
    전담 인력담당 PM 고정 + 백업 인력 명시매번 다른 담당자
    데이터 접근권광고주가 GA4·네이버 광고 관리자 직접 접근대행사만 보유 → 인계 시 분쟁
    리스크 공유성과 미달 환불·재작업 + 데이터 무손실 인계 보증위험을 광고주가 모두 부담

    6. 계약·인계 시 반드시 챙겨야 할 7가지

    좋은 대행사를 골라도 계약이 끝날 때 계정·데이터가 넘어오지 않으면 처음부터 다시 시작해야 합니다. 계약서에 넣을 7가지입니다.

    1. 광고 계정 소유권 — 네이버·구글·메타·카카오 광고 계정은 광고주 명의로 만들고 대행사에는 운영 권한만 줍니다. 대행사 명의 계정은 계약이 끝난 뒤 기록째 넘겨받기 어렵습니다.
    2. 도메인·호스팅 소유권 — 랜딩 페이지의 도메인과 호스팅도 광고주 명의로 등록합니다.
    3. 저작권 양도 조항 — 제작물(이미지·영상·카피)의 저작권을 언제, 어디까지 넘기는지 적습니다. 저작재산권을 전부 넘기기로 해도 특약이 없으면 2차적저작물 작성권은 넘어오지 않은 것으로 추정되므로(저작권법 제45조 제2항) 이 권리도 따로 적습니다.
    4. 데이터 인계 형식 — 계약 종료 때 GA4·픽셀·광고 관리자 데이터를 어떤 형식으로, 언제까지 넘기는지 적습니다.
    5. 예산 집행 투명성 — 매체비와 대행 수수료를 나눠 청구받고, 매체비는 가능하면 광고주 결제 수단으로 직접 결제합니다.
    6. 최소 운영 기간·위약금 — 운영 기간과 위약금 계산 방식을 적고, 지나치게 긴 묶음 조항은 피합니다.
    7. 비밀유지·경업금지 범위 — 같은 업종 경쟁사 동시 운영을 막으려면 업종·지역·기간을 구체적으로 적습니다.

    계약 전에 이 7가지를 정해 두면 계약이 끝날 때 계정·데이터·제작물을 두고 다툴 일이 줄어듭니다.

    자주 묻는 질문

    CPA 광고에서 DB 1건 단가는 어떻게 정하나요?

    업종 시세표보다 내 손익으로 계산하는 편이 정확합니다. 계약 1건으로 남는 이익에 DB가 계약으로 이어지는 비율을 곱하면 DB 1건에 쓸 수 있는 최대 금액이 나옵니다. 예를 들어 신청 10건 중 1건이 계약되고 계약 1건 이익이 30만 원이라면 DB 1건에 쓸 수 있는 돈은 3만 원까지입니다.

    CPA 대행사 견적서와 계약서에서 무엇을 확인해야 하나요?

    견적은 매체비·운영비·콘텐츠 제작비·DB 단가를 나눈 항목별 견적으로 받습니다. 계약서에는 전환의 정의와 무효 DB 기준·검수 기간, 광고 계정을 광고주 명의로 두고 대행사는 운영 권한만 갖는다는 조항, 계약 종료 때 데이터 인계 형식과 기한을 적습니다.

    내 블로그가 저품질에 걸렸는지 어떻게 확인하나요?

    저품질은 업계에서 쓰는 말로, 네이버가 판정 기준이나 회복 기간을 공개한 자료는 찾을 수 없습니다. 블로그 통계에서 유입 검색어가 언제부터 줄었는지 보고, 최근 글 제목으로 검색해 글 하나가 빠진 것인지 블로그 전체가 줄어든 것인지 구분합니다. 다른 곳의 문장·사진을 가져온 글이나 리워드 앱으로 만든 검색·클릭이 없었는지도 확인합니다.
