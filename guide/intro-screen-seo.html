홈페이지 인트로 화면은 검색 순위에 불리할까

#SEO·AI검색2026.10.09노아 편집팀

로고 애니메이션·브랜드 영상·“잠시만 기다려 주세요” 화면.

같은 인트로라도 구현 방식에 따라 노아 메인의 LCP 실측값은 3.54초와 0.17초로 갈렸습니다.

이 글은 구글 검색 센터 가이드와 노아 메인에서 직접 잰 수치로, 인트로를 넣어도 되는 조건을 정리했습니다.

⚡ 3줄 요약

  • 구글은 화면 전체를 덮는 오버레이를 피해야 할 실수로 꼽습니다. 검색 결과에서 넘어온 순간 본문이 바로 보여야 합니다.
  • 인트로가 떠 있는 동안 본문을 그리지 않으면 LCP가 인트로 길이만큼 늦어집니다. 노아 메인은 본문을 미리 그리도록 바꾸자 실측 LCP가 3.54초에서 0.17초로 줄었습니다.
  • 검색 로봇에게만 인트로를 숨기면 클로킹으로 오해받을 수 있습니다. 사람과 로봇은 똑같이 대하고, 검색 결과로 들어온 방문자만 인트로를 건너뛰게 합니다.

홈페이지 인트로 화면은 검색 순위에 불리한가요?

인트로 화면 자체가 감점 항목은 아니지만, 검색 결과를 눌러 들어온 방문자의 본문을 가리면 불리해질 수 있습니다. 구글 검색 센터는 화면 전체를 덮는 인터스티셜을 피해야 할 실수로 분류하고, 사용자와 검색엔진이 페이지에 도착하자마자 콘텐츠에 닿을 수 있어야 한다고 안내합니다.

구글은 2016년 8월 공지에서 2017년 1월 10일 이후 모바일 검색 결과에서 넘어온 순간 콘텐츠에 쉽게 접근할 수 없는 페이지는 순위가 낮아질 수 있다고 밝혔고, 이 내용은 2021년 12월 검색 센터의 정식 가이드 문서로 옮겨졌습니다. 예외는 연령 확인처럼 법적으로 필요한 경우입니다.

그래서 판단 기준은 인트로가 있느냐가 아니라 검색으로 들어온 방문자가 인트로를 만나느냐입니다. 회사 주소를 직접 입력하거나 공유 링크로 들어온 방문자에게 짧은 브랜드 연출을 보여주는 것과, 정보를 찾아 검색 결과를 누른 방문자를 막아서는 것은 다른 문제입니다.

인트로가 로딩 지표(LCP)를 얼마나 늦추나요?

노아 메인(noahgroup.co.kr)에 2.6초짜리 로고 인트로를 넣은 뒤, 구글 PageSpeed Insights와 같은 측정 엔진인 Lighthouse 12의 모바일 설정으로 쟀습니다. 2026년 10월 9일에 같은 조건으로 세 가지 상태를 비교했습니다.

측정 조건은 로컬 서버에서 외부 폰트·분석 스크립트를 막은 실험실 환경입니다. ‘인트로 + 본문 미리 그림’과 ‘인트로 없음’ 열에는 첫 화면 표시를 막던 웹폰트 스타일 파일을 비동기로 바꾸고, 데스크톱 전용 스크롤 라이브러리를 모바일에서 받지 않게 한 개선이 함께 들어 있습니다. 실제 방문자 기준 수치는 서치콘솔 코어 웹 바이탈 보고서에서 28일 단위로 따로 확인해야 합니다.

구글이 정한 LCP 기준은 2.5초 이하가 좋음, 4초 초과가 나쁨이며, 방문의 75% 이상이 기준을 넘어야 통과로 봅니다. 첫 구현의 실측 3.54초는 ‘개선 필요’ 구간이었습니다.

같은 인트로인데 왜 LCP가 3.54초와 0.17초로 갈렸나요?

LCP는 화면에서 가장 큰 요소가 처음 그려진 시점을 재고, 그 요소가 다른 것에 가려져 있었는지는 따지지 않기 때문입니다.

첫 구현에서는 인트로가 끝난 뒤에 첫 화면 문구가 나타나도록 등장 연출을 미뤘습니다. 그러자 가장 큰 요소인 ‘NOAH’ 제목이 인트로가 걷힌 3초 이후에야 그려졌고, 실측 LCP가 3.54초로 늦어졌습니다.

개선 후에는 인트로 아래에서 본문을 미리 그려 두고, 인트로가 걷히기 시작하는 순간(아직 불투명할 때) 숨겼다가 등장 연출을 다시 재생합니다. 방문자가 보는 순서는 같지만 본문이 처음 그려지는 시점이 앞당겨져 실측 LCP가 0.17초가 됐습니다.

다만 이 수치가 기다림이 없다는 뜻은 아닙니다. 인트로가 떠 있는 2.6초 동안 방문자는 여전히 본문을 읽을 수 없습니다. 지표는 좋아져도 체감 대기는 남기 때문에, 노아는 검색으로 들어온 방문자에게는 인트로를 띄우지 않습니다.

검색 로봇에게만 인트로를 숨기면 되지 않나요?

권하지 않습니다. 사용자 에이전트로 검색 로봇을 골라 다른 화면을 보여주면, 검색엔진과 사용자에게 다른 콘텐츠를 보여 순위를 조작하는 구글 스팸 정책의 클로킹으로 오해받을 수 있습니다.

노아도 첫 구현에서는 검색 로봇에게만 인트로를 숨겼다가 이후 이 방식을 없앴습니다. 지금은 사람과 로봇을 구분하지 않고 방문 경로만 봅니다. 구글·네이버·다음·빙 같은 검색 결과에서 들어온 방문자는 인트로 없이 바로 본문을 보고, 주소를 직접 입력하거나 카카오톡 공유 링크로 들어온 첫 방문자만 24시간에 한 번 인트로를 봅니다.

인트로를 넣는다면 어떤 조건을 지켜야 하나요?

아래 7가지는 노아 메인에 실제로 적용한 값입니다. 앞의 두 가지는 검색 순위, 다섯 번째는 속도 지표, 나머지는 방문자 경험과 사고 방지를 위한 조건입니다.

그래서 지금 무엇부터 하면 되나요?

오늘 할 것
  • 휴대폰으로 구글과 네이버에서 내 회사를 검색해 결과를 누르고, 인트로나 팝업이 본문을 가리는지 확인합니다.
이번 주 할 것
  • PageSpeed Insights 모바일 탭에서 LCP를 기록하고, 인트로를 검색 유입 제외·24시간 1회로 바꾼 뒤 같은 조건으로 다시 잽니다.

자주 묻는 질문

인트로는 몇 초가 적당한가요?
정해진 공식 기준은 없습니다. 다만 구글이 정한 LCP 좋음 기준이 2.5초라는 점을 생각하면, 인트로가 이보다 길면 방문자가 첫 화면에서 기다리는 시간이 본문 표시 기준보다 길어집니다. 노아 메인은 2.6초 뒤 자동으로 사라지고, 클릭·탭·키보드·스크롤 중 하나만 해도 바로 닫히게 만들었습니다.
모바일에서만 인트로를 끄면 되나요?
구글의 인터스티셜 기준은 모바일 검색 결과에서 넘어온 순간을 특히 중요하게 봅니다. 그러나 PC에서도 검색으로 들어온 방문자를 막아서는 것은 같은 문제이므로, 기기보다 방문 경로(검색 결과 유입 여부)로 나누는 편이 정확합니다. 노아 메인은 PC·모바일 모두 검색 결과에서 들어오면 인트로를 띄우지 않습니다.
인트로를 넣은 뒤에는 무엇을 확인하나요?
두 가지입니다. 서치콘솔 URL 검사의 실제 페이지 테스트 스크린샷으로 구글이 본문을 읽는지 확인하고, 4주 뒤 코어 웹 바이탈 보고서에서 모바일 LCP가 2.5초 이하인지 봅니다. 실험실 점수가 좋아도 실제 방문자 수치가 나쁘면 실제 방문자 수치가 기준입니다.

NOAH가 인트로를 다루는 방식

이 글의 수치는 노아 메인 페이지에 인트로를 넣고 직접 잰 결과입니다. 지금 사이트에 인트로나 전면 팝업이 있다면 PageSpeed 결과를 보내 주세요. 상담에서 검색 유입을 가리는지, LCP를 늦추는지 무료로 짚어 드립니다. 상담 후 결정은 안 하셔도 됩니다.
