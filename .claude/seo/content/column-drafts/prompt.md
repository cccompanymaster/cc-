# 노아 마케팅 칼럼 집필 — 배정된 10편의 원고 JSON 작성

오늘은 2026-10-22. 노아(noahgroup.co.kr)는 블로그·플레이스·체험단·광고 대행을 하는 마케팅 실행사다. `/column/`에 새 칼럼 50편을 추가하며, 당신은 그중 10편을 쓴다.
HTML은 오케스트레이터가 생성기로 만든다. **당신은 글마다 JSON 원고 1개만 쓴다.**

## 먼저 읽을 파일 (모두 /tmp/claude-0/-home-user-cc-/4bfefe96-3d04-5e46-9231-cf24ab335e46/scratchpad/col50/)
- `plan.json`: 50편 계획. 당신 몫은 배정된 slug만. 각 항목: slug·cat·keyword(대상 검색어)·h1_main·h1_sub·angle(다룰 각도)·verify(공식 출처로 확인할 것)
- `first_party.md`: 노아 자사 사실(공개 가격표). **노아 수치는 이 파일에 있는 것만** 쓴다
- `links.md`: 내부 링크 후보(칼럼 기준 상대 경로). 여기 있는 경로만 링크한다
- 참고용 품질 기준 예시: /home/user/cc-/guide/kakao-link-preview-cache.html, /home/user/cc-/guide/ga4-cta-key-event.html (구성·밀도·직답 방식)

## 절대 규칙
1. **저장소 파일을 수정하지 않는다. git 명령 금지.** 출력은 `specs/<slug>.json`에만 쓴다.
2. **지어내지 않는다.** 근거 없는 통계·비율·평균 단가·사례 수치·"고객 n곳"·연구 결과 금지. 숫자는 ① 공식 출처(법령·정부·플랫폼 공식 도움말)로 확인한 것 ② first_party.md의 노아 가격 ③ 누구나 확인 가능한 상식적 단위(예: 1년=12개월)만. 시장 시세가 궁금한 주제는 숫자 대신 **가격이 정해지는 요소**로 답한다.
3. **법령·플랫폼 정책은 확인한 것만.** 확인하면 sources에 공식 URL을 넣는다. 확인 못 하면 단정하지 말고 빼거나 "○○에서 최신 기준을 확인해야 한다"로 쓴다. 의료·법률·보험·부동산 규정은 특히 조문 번호·기관명을 정확히.
4. **정책 위반 전술을 권하지 않는다**: 가짜 리뷰, 리뷰 대가 조건 지급, 가계정, 키워드 도배, 뒷광고, 순위 보장, 저작권 침해, 경쟁사 비방. 해당 주제는 "왜 위험한지"로 다룬다.
5. **글마다 고유해야 한다.** 다른 글에도 들어갈 수 있는 일반론 문단("광고는 설계하는 것입니다" 류) 금지. 업종·직군 글은 그 업종만의 고객 검색어, 의사결정 과정, 규제, 채널, 체크리스트로 채운다. 같은 배치 안에서도 문장을 재사용하지 않는다.
6. 문체: 합니다체. 짧고 구체적으로. AI 티(번역투 "~에 대해", "다양한", "효과적으로", "~를 통해" 남발, "결론적으로", 기계적 3단 나열, 과한 볼드, 이모지, 감탄) 금지. "최고·1위·무조건·100%·보장" 금지.
7. 노아 언급은 `noah` 필드 한 문단(주제 맞춤, 2~3문장)만. 본문에서 노아 홍보 금지.

## 웹 검색
- WebSearch 최대 **35회**(다른 에이전트와 턴당 200회를 나눠 씀). 공식 도메인(law.go.kr, ftc.go.kr, korea.kr, nts.go.kr, kca.go.kr, searchad.naver.com, help.naver.com, support.google.com, youtube.com/howyoutubeworks, business.instagram.com 등)으로 좁혀 검색한다.
- WebFetch는 이 환경에서 동작하지 않는다(모든 도메인 DNS 실패). 검색 결과 요약에 나온 공식 문장만 근거로 쓴다.
- 확인 못 한 것은 쓰지 않는다. 그게 이 작업의 품질 기준이다.

## 글 구조 (SEO 조건)
- 대상 검색어(keyword)를 h1 앞부분, title, description 앞부분, 첫 문단(lead)에 자연스럽게 넣는다
- `lead`: **첫 문장이 검색 질문에 대한 직답**. 1~2문장, 60~130자
- `sections`: 4~6개. h2는 사람들이 실제로 검색할 법한 **질문형**. 각 섹션 본문 2~4문단(+목록 가능). 본문 합계 2,500~4,000자(공백 포함, lead·FAQ 제외)
- `table`: 1개 필수. caption에 기준일 표기(예: "… (2026-10-22 기준)" 또는 "… (출처명, 2026-10 확인)"). 3~6행. 비교표·체크표·비용 구성표 등
- `checklist`: 4~6항목, 바로 실행할 수 있는 문장
- `faq`: 3개. h2와 다른 질문. 답은 2~4문장, 첫 문장이 직답
- `related`: 3~5개, links.md의 경로만. 같은 주제 칼럼·가이드·아티클과 새 50편 중 가까운 글
- 본문 안 링크는 links.md 경로로만, 문장 속에 자연스럽게 1~3개
- `title`: "키워드 — 부제" 형태, 공백 포함 34자 이내 권장
- `description`: 80~120자, 키워드로 시작하거나 앞 20자 안에, 글이 주는 답의 요지

## 출력 JSON 스키마 (UTF-8, 글 하나당 파일 하나: specs/<slug>.json)
```json
{
 "slug": "plan.json의 slug 그대로",
 "cat": "plan.json의 cat 그대로",
 "keyword": "대상 검색어",
 "keywords": ["대상 검색어", "변형 2~3개"],
 "h1_main": "plan.json 값을 쓰되 더 나은 표현이면 수정 가능 (쉼표로 끝남)",
 "h1_sub": "부제",
 "title": "키워드 — 부제",
 "description": "80~120자",
 "lead": "직답 1~2문장",
 "sections": [{"h2": "질문형 소제목?", "html": "<p>…</p><ul><li>…</li></ul>"}],
 "table": {"after_section": 0, "caption": "표 제목 (기준일)", "head": ["열1","열2"], "rows": [["…","…"]]},
 "checklist": {"title": "체크리스트 제목", "items": ["…"]},
 "faq": [{"q": "질문?", "a": "답"}],
 "noah": "노아는 … (2~3문장, 가격은 first_party.md 그대로)",
 "cta_title": "CTA 제목 한 줄 (예: 내 매장 키워드부터 진단받으세요)",
 "related": ["slug.html", "../guide/x.html"],
 "sources": [{"name": "기관·문서명", "url": "https://공식주소"}],
 "notes": "확인 못 해서 뺀 것, 판단이 필요한 것"
}
```
- html 허용 태그: p, ul, ol, li, b, a(href는 links.md 경로만). 따옴표는 JSON 이스케이프.
- `after_section`: 표를 넣을 섹션 인덱스(0부터).

## 끝내기 전 자체 검사 (Python으로 직접)
- JSON 파싱, 필수 필드, 섹션 4~6, FAQ 3, 표 1, 본문 글자 수 2,500~4,000
- 금지어(최고·1위·무조건·100%·보장) 없음, 링크가 links.md에 있는 경로인지
- 배정된 글끼리 40자 이상 같은 문장 없음
- 글 하나 끝날 때마다 파일을 저장한다(중간에 끊겨도 남도록)

마지막 메시지: 3줄 요약(완료 편수 / 사용한 검색 횟수 / 확인 못 해 뺀 주요 내용).
